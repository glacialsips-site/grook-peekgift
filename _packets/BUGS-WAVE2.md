## MINOR — polish / smell

- `atelier/lib/anthropic/tools/share_to_social.ts:38-42` — `confirm` schema declares both `type: 'boolean'` and `enum: [true]`. JSON Schema permits this but Anthropic's tool input parser may surface the boolean-enum as a string in some SDK versions. Use `const: true` per draft-2019-09 if supported, or just `type: 'boolean'` + server-side check.
- `atelier/lib/anthropic/tools/set_movie_card.ts:11` + `set_song_card.ts:12` — Zod `.refine((x) => x.tmdb_id || x.query)` is not reflected in the JSON `input_schema` `required` field. Anthropic sees no constraint → model can call with neither and ZodError is its first signal. Add `anyOf: [{required: ['tmdb_id']}, {required: ['query']}]` to input_schema.
- `atelier/lib/anthropic/system-prompt.ts:115-176` (BASE_PROMPT) — `web_search_tool_bm25` mentioned at line 150 is actually two tools: `web_search` (server) for live results, `tool_search_tool_bm25` for tool discovery. The base prompt blurs them.
- `atelier/lib/anthropic/server-tools.ts:39-43` — `WEB_SEARCH_MAX_USES ?? 5` — five searches per turn is generous; with a 10-iteration cap and stub-heavy first turn, the model could burn the search budget before producing any cards. Consider 2-3 as default.
- `atelier/lib/anthropic/server-tools.ts:48-49` — `WEB_FETCH_MAX_USES ?? 3`, `max_content_tokens: 50_000` — 50K tokens per fetch × 3 fetches = up to 150K tokens of fetched content per turn entering the context window. With Block 1+2+3+tools already at 30K+, you can exhaust context quickly. Cap content tokens lower (e.g. 15K).
- `atelier/lib/anthropic/skills/copy-house-style.ts` is `30KB`, auto-generated from markdown; the build bundles the full skill in EVERY edge function bundle including ones that don't use it (e.g. `/api/og/*`, `/api/share/send`). Verify Next tree-shakes; if not, lazy-import.
- `atelier/lib/anthropic/tools/set_movie_card.ts:23` — `type: 'integer'` for `tmdb_id` matches Zod but ImagineSearch+Plex tooling sometimes treats TMDB IDs as strings; future packet 42 wiring should accept both.
- `atelier/lib/anthropic/tools/propose_payment_method.ts:6-16` — 9 payment-method enum values hardcoded; if Stripe adds new methods (Klarna Pay-in-4, etc.) they're not in the enum. Acceptable for stub; flag for packet 45.
- `atelier/lib/anthropic/tools/affiliate_search.ts:39` — wellness/food_and_drink categories are inconsistent with `add_card.ts` type enum which doesn't have wellness/food. Cross-tool category vocabulary needs a unified taxonomy file.
- `atelier/lib/anthropic/tools/attach_files_api_ref.ts:64-89` — race condition: two parallel `attach_files_api_ref` calls on the same peek can both read `active_attached_file_ids`, both append, and the second clobbers the first (transaction-less read-modify-write on JSONB column). Same pattern as B13 (carryover) but on different field. Single-tool-call-at-a-time per turn usually saves you, but parallel tool_use in one assistant response breaks it.
- `atelier/lib/anthropic/extended-thinking.ts:13-22` — `requestExtendedThinking` and `consumeExtendedThinking` share state via a process-local Map. No telemetry on `request_extended_thinking` actually firing successfully (it just sets the flag) vs. being consumed. Hard to debug when ext-thinking isn't producing expected output.
- `atelier/app/api/upload/anthropic/route.ts:24` — `MAX_SIZE = 500 MB` per file. Netlify Function payload limit is ~6MB on the synchronous path. Files >6MB will OOM the route before `uploadToFilesApi` even runs.
- `atelier/app/api/upload/anthropic/route.ts:111-138` — On the metadata persist failure path, `log.error` fires but the route still returns 200 + the file_id. Curator sees "success" but the file_id never makes it into `peeks.metadata.uploaded_files`, so `attach_files_api_ref` can't find it. Should return 500 or at least surface a warning to the client.
- `atelier/lib/anthropic/tools/request_voice_capture.ts:46-57` — Returns `voice_mode_not_available` error when DEEPGRAM_API_KEY or ELEVENLABS_API_KEY is unset. But the `not_implemented_yet` return below it ALWAYS fires when keys ARE set (since voice capture isn't implemented). So the tool ALWAYS returns `ok: false` regardless of key state. The `voice_mode_not_available` branch is dead until packet 43.
- `atelier/lib/anthropic/memory/store.ts:96-109` — `view` returns lines with line-number prefix `String(i+1).padStart(6, ' ')` + tab. That matches Anthropic Memory spec, but `padStart(6, ' ')` for files >999999 lines doesn't truncate gracefully. Not a real risk (50KB file caps ~1500 lines) but odd.
- `atelier/lib/anthropic/system-prompt.ts:160-176` (BASE_PROMPT) — `gabagool` owner-escape-hatch is sent to Anthropic on EVERY chat turn as part of the cached system prompt. Anyone with debug access to PostHog `$ai_input` traces sees the secret. Move escape-hatch logic server-side (route.ts checks user message, skips guardrails if match) so the secret isn't in the prompt.
- `atelier/app/api/chat/route.ts:194-259` — Files-API injection drains `active_attached_file_ids` BEFORE the chat turn runs. If the chat turn errors mid-stream, the file_ids are GONE from metadata but the model never saw them. Re-attach requires the model to call `attach_files_api_ref` again. Drain-after-success would be more correct.
- `atelier/lib/anthropic/tools/set_curator_memory.ts:57-60` — On Zod failure returns `error: 'invalid_key'` even when the actual failure is `value` shape or `expires_at` format. Misleading error code.
- `atelier/lib/anthropic/server-tools.ts:62-65` — Memory tool descriptor has no `allowed_callers` constraint. SDK type `MemoryTool20250818.allowed_callers` accepts `['direct', 'code_execution_20250825', 'code_execution_20260120']`. Without scoping, code_execution can call memory directly — chain-of-trust unclear.

## ANTI-FINDINGS — looked like bugs, aren't

- **Cache breakpoint count.** System (3) + tools (1) = 4 exactly — at the maximum, but not exceeding it. Moderation runs in a separate `messages.create` call (own cache budget). `cache-breakpoints.test.ts:275-288` already asserts the maximum holds. (Audit caveat: see W01 — the breakpoints are AT max, but they may not be RECOGNIZED at 1h TTL without the beta header. Different concern.)
- **affiliate_search registration gate.** Looked initially like the tool was hidden behind `if (env.SKIMLINKS || env.SOVRN)` — actual file unconditionally registers. The hidden-tool comment in an earlier draft was removed.
- **Default model in `claude-opus-4-7`.** Pre-existed packet 40/41 (it was already opus in `8df4e78`), but per W04 the SPINE update at 4ce5db9 declares Sonnet as the default. The code never caught up — counting as a NEW finding because the spec divergence was introduced by this session's spine update.
- **`as unknown as Anthropic.ContentBlockParam`** at `app/api/chat/route.ts:227,235` — needed because the file_id source isn't in the typed union when the beta header is set globally. Pre-existing pattern; not a NEW type hole.
- **In-memory `TOOL_REGISTRY` Map.** `tools/index.ts:17` — module-scope Map populated by side-effect bootstrap imports. Process-restart resets it but `bootstrap.ts` re-imports on cold start. Fine. Not a leak.
- **`peek_v2` schema correctly set on `getSupabaseService`.** `lib/supabase/service.ts:21`. The curator_memory queries work against the right schema.
- **Memory tool's case-insensitive URL-encoded traversal block.** `paths.ts:21` matches `%2e`, `%2f`, `%5c` after lowercasing — correctly defeats encoded `../` and `..\\` traversals.
- **`memory_20250818` is a Beta tool but the typed surface is GA.** The SDK exposes `MemoryTool20250818` as a non-beta type at `messages.create`. No additional beta header needed for the descriptor itself (unlike W01's `extended-cache-ttl`).
- **The 11 stub tools do return `{ok: false, error: 'not_implemented_yet'}`** on the happy path. They CAN throw on schema validation (W09) but the throw is caught by `chat.ts:275-283` and surfaced as `is_error: true` tool_result — chat loop doesn't crash, just emits a sub-optimal user-facing error message.
